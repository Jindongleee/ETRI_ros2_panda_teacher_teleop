## 3.3 실행 방법

### 3.3.1 Joystick 텔레오퍼레이션

```bash
# 1. Joystick 연결 확인
ls /dev/input/js*

# 2. 클러치 페달 연결 확인 (선택사항)
# PCsensor FootSwitch가 연결되어 있어야 함

# 3. Launch
ros2 launch panda_teleop_joystick joystick_teleop.launch.py

# 데이터 수집 활성화 시
ros2 launch panda_teleop_joystick joystick_teleop.launch.py enable_data_collection:=true
```

**조작법**:
1. 클러치 페달을 밟은 상태에서 Joystick 조작
2. Left Stick: XY 평면 이동
3. L1/L2: Z축 상/하 이동
4. Right Stick: Roll/Pitch 회전
5. R1/R2: Yaw 회전
6. Circle/Square: 그리퍼 열기/닫기

### 3.3.2 Vive Tracker 텔레오퍼레이션

```bash
# 1. SteamVR 실행 (별도 터미널)
steam -vr

# 2. Vive 서버 실행 (별도 터미널)
ros2 run vive_ros2 vive_input [frequency]  # 기본: 50Hz

# 3. Launch
ros2 launch panda_teleop_vive panda_teleop_vive.launch.py

# 데이터 수집 활성화 시
ros2 launch panda_teleop_vive panda_teleop_vive.launch.py enable_data_collection:=true
```

**조작법**:
1. Vive 컨트롤러의 트리거를 눌러 기준점(Origin) 설정
2. 클러치 페달을 밟은 상태에서 컨트롤러 이동 → 로봇 EE 추적
3. 트리거 축: 그리퍼 아날로그 제어 (0=열림, 1=닫힘)
4. Menu 버튼: 기준점 리셋

### 3.3.3 OmyL100 텔레오퍼레이션

```bash
# 1. OmyL100 USB 연결 확인
ls /dev/ttyUSB*

# 2. Launch
ros2 launch panda_teleop_omy_l100 panda_teleop_omy_l100.launch.py

# 포트 변경 시
ros2 launch panda_teleop_omy_l100 panda_teleop_omy_l100.launch.py port_name:=/dev/ttyUSB1

# 데이터 수집 활성화 시
ros2 launch panda_teleop_omy_l100 panda_teleop_omy_l100.launch.py enable_data_collection:=true
```

**조작법**:
1. OmyL100 리더 암이 중력 보상 모드로 부팅 (자유 조작 가능)
2. 클러치 페달을 밟으면 텔레오퍼레이션 시작
3. 리더 암을 움직이면 Panda가 RViz에서 추적
4. 리더 암의 그리퍼 → Panda 그리퍼 연동
5. 클러치 페달을 놓으면 일시정지 (리더 암 위치 재조정 가능)
6. 다시 밟으면 현재 위치에서 오프셋 재계산 후 재개

### 3.3.4 시작 타이밍 시퀀스 (공통)

```
t=0s   omy_l100_leader_ai / robot_state_publisher / trajectory_to_joint_states
t=3s   servo_node / twist_node / gripper_node / clutch_pedal_node
t=5s   RViz
t=6s   /servo_node/start_servo 서비스 호출 (Servo 활성화)
t=7s   data_collection_node (선택사항)
```

## 3.4 데이터 수집 상세

### 수집 프로세스

```
[대기] → (클러치 ON) → [수집 중] → (타겟 도달) → [정지 대기 3초]
  ↑         │                                            │
  │         └─ 타겟: 워크스페이스 내 랜덤 위치              │
  │                                                       ▼
  └──────── (다음 에피소드) ←──── [에피소드 종료/저장] ←────┘
                                       │
                                 (3개 완료 시)
                                       ▼
                               [세션 완료/요약 저장]
```

### 입력 장치별 데이터 수집 설정

모든 입력 장치는 **OmyL100과 동일한 수집 파라미터**를 사용한다. (Config 파일 경로와 `controller_type`만 다름)

| 설정 | Joystick | Vive | OmyL100 |
|------|----------|------|---------|
| Config 파일 | `data_collection_config_joystick.yaml` | `data_collection_config_vive.yaml` | `data_collection_config_omy_l100.yaml` |
| 수집 레이트 | 20 Hz | 20 Hz | 20 Hz |
| 에피소드 수 | 3 | 3 | 3 |
| 에피소드 타임아웃 | 20초 | 20초 | 20초 |
| 정지 지속 시간 | 1초 | 1초 | 1초 |

### 수집 데이터 형식

**State** (상태):
```json
{
  "ee_pose": [x, y, z, qx, qy, qz, qw],
  "joints": [j1, j2, j3, j4, j5, j6, j7]
}
```

- `ee_pose`: TF lookup (`panda_link0` → `gripper_tip_link`)으로 획득
- `joints`: `/joint_states`에서 처음 7개 조인트 값

**Action** (행동):
```json
{
  "delta_twist": [vx, vy, vz, wx, wy, wz]
}
```

- `/servo_node/delta_twist_cmds`에서 획득
- 선속도(m/s) + 각속도(rad/s)

**핵심 원리**: `state[i]`에서 `action[i]`를 실행하면 `state[i+1]`이 된다.

## 3.5 디버깅 가이드

### 공통 체크 명령어

```bash
# 토픽 목록 확인
ros2 topic list

# 특정 토픽 모니터링
ros2 topic echo /servo_node/delta_twist_cmds
ros2 topic echo /joint_states
ros2 topic echo /clutch/active

# 토픽 발행 주파수 확인
ros2 topic hz /servo_node/delta_twist_cmds
ros2 topic hz /joint_states

# 노드 목록 확인
ros2 node list

# TF 트리 확인
ros2 run tf2_tools view_frames

# 노드 그래프 시각화
rqt_graph
```

### 문제별 해결 가이드

| 증상 | 원인 | 해결 |
|------|------|------|
| RViz에서 로봇이 안 보임 | `robot_state_publisher` 미시작 또는 URDF 경로 오류 | `ros2 topic echo /robot_description` 확인 |
| 로봇이 움직이지 않음 | Servo 미활성화 | `ros2 service call /servo_node/start_servo std_srvs/srv/Trigger` |
| 클러치 페달 미인식 | evdev 권한 없음 | `sudo usermod -a -G input $USER` + 재로그인 |
| OmyL100 연결 실패 | USB 포트 오류 | `ls /dev/ttyUSB*` 확인 후 `port_name` 파라미터 변경 |
| "TF lookup failed" 반복 | OmyL100 TF 미발행 | `ros2 topic echo /leader/joint_states`로 데이터 수신 확인 |
| Servo가 명령 무시 | 속도 값이 너무 작음 | 스케일 파라미터 증가 또는 Servo `incoming_command_timeout` 확인 |
| 그리퍼가 안 움직임 | `/gripper/position` 미발행 | `ros2 topic echo /gripper/position` 확인 |
| Vive 연결 불가 | SteamVR 미실행 | `steam -vr` 먼저 실행 후 `vive_input` 시작 |

## 3.7 공학 용어 요약 (Glossary)

| 용어 | 설명 | 사용 위치 |
|------|------|-----------|
| **FK (Forward Kinematics)** | 조인트 각도 → 엔드이펙터 포즈 변환 | OmyL100 리더 암 (TF 기반) |
| **IK (Inverse Kinematics)** | 엔드이펙터 포즈/속도 → 조인트 명령 변환 | MoveIt Servo (KDL 기반) |
| **Jacobian** | 조인트 속도와 Cartesian 속도의 관계 행렬 | MoveIt Servo 내부 (속도 IK) |
| **Pseudo-inverse (J⁺)** | 비정방 Jacobian의 일반화 역행렬 | 7-DOF 로봇의 IK 풀이 |
| **Singularity** | Jacobian rank 감소로 IK가 불안정한 자세 | Servo 특이점 감지/회피 |
| **Quaternion** | 3D 회전 표현 (w, x, y, z), 짐벌 락 없음 | 모든 방향 데이터 |
| **Axis-Angle** | 회전축 + 각도로 회전 표현 | 각속도 계산 시 중간 변환 |
| **SLERP** | 쿼터니언의 구면 선형 보간 | Vive 포즈 필터링 |
| **Cartesian Space** | 작업 공간 좌표 (x, y, z + 자세) | EE 포즈, TwistStamped |
| **Joint Space** | 각 조인트의 각도 공간 | JointState, JointTrajectory |
| **TwistStamped** | 선속도 + 각속도 (6-DOF) | Servo 입력 |
| **Rate Control** | 입력에 비례한 속도 출력 | Joystick 제어 |
| **Position-Velocity Mapping** | 위치 차분으로 속도 생성 | Vive, OmyL100 제어 |
| **Gravity Compensation** | 로봇 자중에 의한 토크 보상 | OmyL100 Leader 모드 |
| **Impedance Control** | 위치/힘의 관계를 스프링-댐퍼로 모델링 | 관련 개념 (직접 구현 X) |
| **Admittance Control** | 힘 입력 → 위치/속도 출력 | 관련 개념 (직접 구현 X) |
| **DH Parameters** | Denavit-Hartenberg 파라미터, 링크/조인트 기하 정의 | URDF에 암묵적 포함 |
| **KDL** | Kinematics and Dynamics Library | IK 솔버, 중력 보상 |
| **Butterworth Filter** | 주파수 기반 저역통과 필터 | Servo 출력 스무딩 |
| **Low-pass Filter** | 고주파 노이즈 제거 필터 | Vive 포즈 필터링 |
| **Deadzone** | 입력 임계값 이하 무시 영역 | Joystick 드리프트 방지 |
| **Clutch (Hold-to-Activate)** | 안전 장치, 누르고 있을 때만 동작 | 모든 텔레오퍼레이션 모드 |
| **Leader-Follower** | 리더 로봇의 동작을 팔로워가 추종 | OmyL100(Leader) → Panda(Follower) |
| **Imitation Learning** | 시범 데이터로 정책 학습 | 데이터 수집 목적 |
| **State-Action Pair** | (상태, 행동) 쌍, MDP 기본 단위 | JSONL 데이터 구조 |
| **ros2_control** | ROS2 표준 하드웨어 추상화 프레임워크 | Dynamixel 하드웨어 인터페이스 |
| **MoveIt Servo** | 실시간 텔레오퍼레이션용 MoveIt 모듈 | 속도 명령 → 조인트 궤적 변환 |
